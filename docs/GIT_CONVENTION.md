# Git Convention

## Branches

- `main`: 배포 가능한 기준 브랜치. 직접 push하지 않는다.
- `dev`: 통합 브랜치.
- `feature/{domain}-{detail}`: 기능 개발.
- `fix/{domain}-{detail}`: 버그 수정.
- 초기 구성, 문서, 저장소 유지보수는 사용자의 명시적인 요청이 있을 때만 `dev`에 직접 반영할 수 있다.

## Commit

```text
type: 한국어 작업 요약
```

허용 type:

- `feat`: 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 변경
- `style`: 코드 동작과 무관한 형식 변경
- `refactor`: 기능 변경 없는 구조 개선
- `test`: 테스트 추가·변경
- `chore`: 빌드, 설정, 의존성, 저장소 유지보수
- `design`: UI와 스타일 변경
- `comment`: 주석 변경
- `rename`: 파일·식별자 이름 변경
- `remove`: 코드·파일 제거
- `!HOTFIX`: 운영 긴급 수정

규칙:

- 제목은 50자 안팎의 명령형 한국어로 작성한다.
- 커밋 하나에는 하나의 목적만 담는다.
- 본문이 필요하면 변경 이유와 영향을 적는다.
- 관련 이슈가 있으면 footer에 `Refs: #번호`를 적는다.

예시:

```text
feat: 채용공고 조회 API 구현

- 사람인 공고 목록을 내부 응답 형식으로 변환
- 마감된 공고를 기본 조회에서 제외

Refs: #12
```

## Pull Request

- 대상 브랜치는 `dev`다.
- 제목 형식은 `[타입] #이슈번호 제목`이다.
- 이슈가 없으면 `[타입] 제목`을 사용한다.
- 목적, 주요 변경, 검증 결과, 리뷰 포인트, API·DB 변경 여부를 작성한다.
- merge 전 build와 test 성공, 충돌 없음, 체크리스트 완료를 확인한다.
