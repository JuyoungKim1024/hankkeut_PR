# External Services

한끗 로컬 앱에 필요한 외부 연동과 준비 시점을 정리합니다. 현재 즉시 필요한 외부 API는 없습니다. 비밀값은 채팅이나 Git에 남기지 않고 `backend/.env`에만 저장합니다.

## 공통 원칙

- fixture와 stub으로 계약과 실패 처리를 먼저 구현합니다.
- 라이브 호출 직전에 선택한 서비스의 credential만 요청합니다.
- API 없이 구현 가능한 로컬 기능에는 외부 서비스를 추가하지 않습니다.
- credential, 수집 원문에 포함된 개인정보, 이력서 내용은 로그에 남기지 않습니다.

## 채용공고 데이터

외부 채용 API를 사용하지 않습니다. 사용자가 브라우저에서 확인한 공고의 URL과 필요한 본문을 직접 한끗에 등록합니다.

- 별도 API key나 서비스 승인이 필요하지 않습니다.
- 같은 URL을 다시 등록하면 기존 공고를 갱신합니다.
- 자동 검색 결과 크롤링, 로그인, CAPTCHA, 유료벽, 접근통제 또는 차단 우회는 하지 않습니다.
- 원문 전체를 재배포하지 않고 로컬 취업 준비에 필요한 범위에서만 저장합니다.
- 추후 브라우저 확장이나 북마클릿을 추가하더라도 사용자가 선택한 공개 공고 한 건을 명시적으로 저장하는 흐름을 유지합니다.
- 자동 수집 소스를 추가할 때는 해당 사이트의 약관과 robots 지침이 허용하는지 먼저 확인합니다.
- 자동 수집 소스가 없는 동안 Scheduler는 기본 비활성화합니다.

## OpenAI API

공고 기술 추출, 사용자 경험 구조화, 부족 기술 학습, 자기소개서 초안과 면접 질문 생성에 사용할 예정입니다. 규칙 기반 또는 로컬 모델로 대체하지 않는다면 AI 기능의 라이브 검증 시 필요합니다.

필요 시 준비할 항목:

- 개발용 OpenAI API project와 제한된 API key
- 사용할 model과 사용량 한도

```env
OPENAI_API_KEY=
OPENAI_PROJECT_ID=
OPENAI_MODEL=
```

## 외부 API가 필요하지 않은 기능

- 로컬 프로필과 기술 스택 관리
- 이력서·포트폴리오 로컬 저장 및 Apache Tika 텍스트 추출
- 공고 저장, 중복 제거, 변경·마감 감지
- 검색, 필터, 관심 공고와 지원 상태 관리
- 로컬 데이터 백업·복원·내보내기
- Docker Compose 기반 로컬 설치와 실행

## 제거된 연동

- Google/Kakao OAuth와 JWT: 로그인 없는 단일 사용자 앱이므로 제거
- Cloudflare R2: 로컬 파일 저장으로 대체
- Vercel 및 백엔드 호스팅: 중앙 사이트를 배포하지 않음

## 앞으로의 기능 순서

1. 로컬 프로필·기술 스택과 이력서 입력 흐름
2. URL·본문 기반 채용공고 수동 등록
3. 공고 중복 제거, 변경·마감 감지
4. 공고 목록·검색·상세 화면
5. OpenAI Gateway와 기술·경험 구조화
6. 적합도, 부족 기술, 추천 근거
7. 학습 자료, 자기소개서 초안, 면접 질문
8. 관심 공고와 지원 단계 관리
9. 로컬 백업·복원과 한 명령 설치 패키지
