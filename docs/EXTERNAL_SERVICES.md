# External Services

한끗 로컬 앱에 필요한 외부 연동과 준비 시점을 정리합니다. 현재 즉시 필요한 외부 API는 없습니다. 비밀값은 채팅이나 Git에 남기지 않고 `backend/.env`에만 저장합니다.

## 공통 원칙

- fixture와 stub으로 계약과 실패 처리를 먼저 구현합니다.
- 라이브 호출 직전에 선택한 서비스의 credential만 요청합니다.
- API 없이 구현 가능한 로컬 기능에는 외부 서비스를 추가하지 않습니다.
- credential, 수집 원문에 포함된 개인정보, 이력서 내용은 로그에 남기지 않습니다.

## 채용공고 데이터

### 공개 페이지 수집

- 별도 API key가 필요하지 않습니다.
- 첫 어댑터 구현 전에 대상 페이지의 이용 조건, robots 지침, 접근 범위와 호출 간격을 확인합니다.
- 로그인, CAPTCHA, 유료벽, 접근통제 또는 차단을 우회하지 않습니다.
- 테스트에서는 저장된 HTML fixture를 사용하고 라이브 네트워크에 의존하지 않습니다.

### 사람인 Open API

선택 사항입니다. 공개 페이지보다 안정적인 식별자·상태·필드를 합법적으로 제공하는 경우에만 추가합니다.

현재 구현 상태:

- 공식 JSON 응답 parser와 페이지 수집 adapter는 fixture로 구현했습니다.
- 실제 HTTP client와 live smoke test는 access key 설정 후 진행합니다.
- 공식 API는 공고 ID, URL, 기업명, 제목, 지역, 직무, 경력, 키워드와 상태를 제공하지만 자격요건·우대사항 전체 본문은 제공하지 않습니다.
- API 데이터를 화면에 표시할 때 사람인 제공 정보임을 명시해야 합니다.

필요 시 준비할 항목:

- 사람인 Open API 사용 신청과 승인
- 발급된 access key
- 일 최대 호출 제한과 요청당 최대 110건 조건 확인
- 저장·노출 가능 필드와 출처 표기 조건 확인

```env
SARAMIN_ACCESS_KEY=
```

Wanted 등 다른 소스도 실제 사용 가능한 공식 계약이 확인될 때 같은 어댑터 경계로 추가합니다.

## OpenAI API

공고 기술 추출, 사용자 경험 구조화, 부족 기술 학습, 자기소개서 초안과 면접 질문 생성에 사용할 예정입니다. 규칙 기반 또는 로컬 모델로 대체하지 않는다면 AI 기능의 라이브 검증 시 필요합니다.

필요 시 준비할 항목:

- 개발용 OpenAI API project와 제한된 API key
- 사용할 model과 사용량 한도

```env
OPENAI_API_KEY=
OPENAI_PROJECT_ID=
OPENAI_MODEL=
```

## 외부 API가 필요하지 않은 기능

- 로컬 프로필과 기술 스택 관리
- 이력서·포트폴리오 로컬 저장 및 Apache Tika 텍스트 추출
- 공고 저장, 중복 제거, 변경·마감 감지
- 검색, 필터, 관심 공고와 지원 상태 관리
- 로컬 데이터 백업·복원·내보내기
- Docker Compose 기반 로컬 설치와 실행

## 제거된 연동

- Google/Kakao OAuth와 JWT: 로그인 없는 단일 사용자 앱이므로 제거
- Cloudflare R2: 로컬 파일 저장으로 대체
- Vercel 및 백엔드 호스팅: 중앙 사이트를 배포하지 않음

## 앞으로의 기능 순서

1. 로컬 프로필·기술 스택과 이력서 입력 흐름
2. 채용공고 공통 소스 계약과 첫 수집 어댑터
3. 수집 멱등성, 변경·마감 감지, Scheduler
4. 공고 목록·검색·상세 화면
5. OpenAI Gateway와 기술·경험 구조화
6. 적합도, 부족 기술, 추천 근거
7. 학습 자료, 자기소개서 초안, 면접 질문
8. 관심 공고와 지원 단계 관리
9. 로컬 백업·복원과 한 명령 설치 패키지
